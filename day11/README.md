# Day11 关键词检索 + 向量检索 + 引用来源

## 今日目标

- 实现关键词检索
- 实现向量检索
- 实现混合检索
- 了解 rerank 和查询改写
- 在回答里返回引用来源

## 关键词检索是什么

关键词检索是按字面匹配找内容。

比如用户问 `小乐`，文档里也正好出现 `小乐`，就能直接命中。

它的优点是简单、直接、快。
缺点是不会理解语义，问题换个说法就可能搜不到。

## 向量检索是什么

向量检索是按语义相似度找内容。

比如用户问 `我的名字叫什么？`，文档里写的是 `我的名字叫小乐`，虽然字面不完全一样，但语义接近，向量检索就能找到。

## 混合检索是什么

混合检索就是把关键词检索和向量检索结合起来。

本项目里：

- 关键词检索负责精确命中
- 向量检索负责语义命中
- 最后把结果合并、去重

这样比只用一种检索更稳。

## rerank 是什么

rerank 可以理解成“二次排序”。

流程通常是：

```text
先召回一批候选 chunk
-> 再对这些 chunk 重新排序
-> 把最有用的排到前面
```

Day11 先理解这个概念，不一定要接真实 rerank 模型。

## 查询改写是什么

查询改写是把用户原始问题改得更适合检索。

例如：

```text
用户问：它提升了吗？
改写后：模型指标是否提升，F1、准确率、召回率变化是多少？
```

这样更容易命中相关文档。

## 当前实现流程

### 1. 关键词检索

通过 SQLite 中的 `chunks` 表，按 `chunk.text.contains(query)` 做字面匹配。

### 2. 向量检索

通过 Chroma 根据 query 的语义向量，找到最相关的 chunk。

### 3. 混合检索

把两种检索结果合并，然后去重。

### 4. 基础 RAG 问答

把检索到的 chunk 拼成 context，交给 DeepSeek 生成答案，并返回引用来源。

## 接口说明

### POST /rag/answer

请求示例：

```json
{
  "user_id": 1,
  "query": "我的名字叫什么？",
  "top_k": 3,
  "temperature": 0.3
}
```

返回示例：

```json
{
  "answer": "根据资料，你的名字叫小乐。",
  "sources": [
    {
      "chunk_id": "chunk:1",
      "filename": "草稿.txt",
      "text": "我的名字叫小乐，请你记住",
      "distance": 0.7835,
      "retrieval_method": "vector"
    }
  ]
}
```

## distance 是什么

`distance` 表示检索距离。

一般来说：

- `distance` 越小，越相关
- `distance` 越大，越不相关

关键词检索里我这里手动写成 `0`，表示“精确命中”。

向量检索里的 `distance` 是 Chroma 计算出来的真实距离。

## 我对 Day11 的理解

Day11 的重点不是把搜索做得很花，而是理解不同检索方式的作用。

关键词检索擅长找精确词，向量检索擅长找语义相近内容，混合检索能让 RAG 更稳，引用来源能让答案更可追溯。

Day11 做完后，系统已经比 Day10 更接近真实项目里的 RAG 检索层了。
