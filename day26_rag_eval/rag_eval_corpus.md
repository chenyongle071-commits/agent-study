RAG 的核心流程是：先检索相关资料，再把资料拼成上下文 context，最后让大模型根据上下文回答。

Embedding 是把文本转换成向量，用向量表示语义相似度。

Top-K 在检索里的意思是返回最相关的前 K 个结果。

Chunk 是把长文档切分出来的一小段文本。

文档要切成 chunk，是为了让系统可以检索更小、更准确的文本片段。

向量数据库的作用是保存文本向量，并根据语义相似度进行检索。

混合检索是把关键词检索和向量检索结合起来。

rerank 是对召回结果重新排序，让更相关的内容排在前面。

RAG 回答要带引用来源，是为了让答案更可信，也方便用户检查来源。

不知道答案时应该拒绝回答，可以说根据当前资料无法回答。

不同用户的数据要隔离，因为每个用户只能访问自己的数据，不能越权访问其他用户资料。

Prompt Injection 的风险是用户试图让模型忽略原本指令，绕过系统规则。

日志脱敏要处理邮箱、token、api_key、password 等敏感信息。

危险操作需要二次确认，因为删除、清空、重置这类高风险操作不能直接执行。

工具选择准确率表示 Agent 有没有选对应该调用的工具。

工具参数正确率表示 Agent 调用工具时有没有填对参数。

任务完成率表示 Agent 最终有没有完成用户提出的任务。

RAG 评估应该关注召回质量、回答事实一致性、引用来源正确性、延迟和 Token 成本。
