1. SSE 流式输出
SSE 是 Server-Sent Events，意思是：
服务端不是一次性把答案全发回来，而是边生成边往前端推。

比如用户问一句话，模型回答很长时，前端会看到：
正在输出...
一段一段地出来...
这比一次性等完整答案更自然。
你可以把它理解成：
普通 /chat：
用户提问 -> 等完整答案 -> 一次返回

SSE /chat/stream：
用户提问 -> 服务端边生成边发 -> 前端实时显示

2. 结构化 JSON 输出
这个意思是：不要让模型随便写一大段散文，而是让它按固定字段输出。
比如你希望返回：
{
  "answer": "RAG 是检索增强生成",
  "model": "deepseek-v4-flash",
  "confidence": 0.82
}
这样后端和前端都更容易处理。
它的意义是：
更容易解析
更适合前端展示
更方便后面做工具调用
更方便做评测

3. 超时、重试、限流
这是工程化必须补的三件事。
超时
意思是：
一个请求不能无限等。

比如：
LLM 30 秒还没回，就直接失败
否则接口会一直挂着。
重试
意思是：
临时网络失败时，可以再试一两次。

比如 DeepSeek 一次连接失败，不一定代表永远失败。
限流
意思是：
不要让一个用户短时间疯狂刷接口。

例如：
同一个用户 1 秒最多请求 1 次
这可以防止：
误触
恶意刷接口
费用暴涨
